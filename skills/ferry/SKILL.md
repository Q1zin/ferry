# ferry: работа на других устройствах

`ferry` ходит в приложение ferry на этой машине, а оно — в связанные устройства. Каждая команда — обычный процесс: вывод потоком, код выхода — устройства. `ferry` без аргументов — полный список команд.

## Сначала

Если подключён MCP-сервер ferry (`claude mcp add ferry -- ferry mcp`) — инструмент `ferry`, `args` — те же аргументы, что ниже после слова `ferry`; снимки приходят картинкой сразу. Иначе — команда в терминале.

```sh
ferry devices --json        # me и peers: name, online, status.role/mode/os/version
```

Цели в командах: имя устройства, несколько через запятую, `all` (все на связи, кто принимает команды), `os:windows`. На нескольких целях строки подписаны `[устройство]`, код — первый ненулевой.

Код **75** — отказ самого устройства: человек за ним включил «не трогать рабочий стол» или «отключён», либо это пульт. Не повторяй — скажи человеку. Исключение — «рабочий стол <устройство> занят: <кто>»: окна и ввод там держит другая сессия (другой агент гоняет тесты). Подожди — `ferry desk <устройство>` покажет, сколько осталось, — или возьми другое устройство; `free --force` — только если человек сказал. Свой долгий GUI-прогон: `ferry desk <устройство> take` перед ним, `free` после. «Не знает команду — обнови: ferry update <устройство>» — у устройства старая версия.

## Код и сборки

Из каталога проекта (git): `ferry run` сначала кладёт на устройство снимок рабочего дерева (с незакоммиченным), потом выполняет команду в том же подкаталоге. Вне репозитория — в домашнем каталоге устройства. На Windows по умолчанию Git Bash; у `run` и `start` есть `--shell default|bash|powershell|cmd` (с ferry 0.1.18 на пульте и устройстве). PowerShell/cmd запускаются напрямую, только на Windows. Для точного кода внешней программы в PowerShell добавь `exit $LASTEXITCODE`.

```sh
ferry run win-10 -- cargo test                      # ждёт конца, код — команды
ferry run win-10 --desk -- bunx playwright test     # --desk: команде нужны окна
ferry run win-10 --no-sync -- 'ls target'           # без снимка проекта
ferry run win-10 --home -- 'ls ~/Downloads'         # из репозитория, но в доме устройства
ferry run win-10 --home --shell powershell -- 'Get-Location'
ferry run win-10 --home --shell cmd -- 'ver & echo %USERPROFILE%'
ferry sync win-10                                   # только снимок — перед start --no-sync
```

Настройки проекта — на этой машине в `~/.ferry/projects/<имя репозитория>.toml`: `files = [".env"]` — что возить мимо git, `tools` — что проверяет `ferry doctor`. Свежий клон получает их сам.

Долгое или то, что должно жить дальше (приложение, dev-сервер, сборка) — фоновой задачей:

```sh
ferry start win-10 app -- ./target/debug/app.exe --remote-debugging-port=9322
ferry log win-10 app -f        # следить; выйдет с кодом задачи — так ждут сборку; обрыв связи
                               #   переживает: дождётся устройства и продолжит с того же места
ferry wait win-10 --log app "ready"   # ждать строку в логе вместо sleep; печатает её (URL и т. п.)
ferry wait win-10 --port 9322         # ждать открытый порт — потом ferry tunnel
ferry jobs win-10 --json       # что работает
ferry kill win-10 app          # гасит всё дерево процессов задачи
ferry stop win-10              # снять все команды и задачи
```

Файлы: `ferry put <цели> <файл>…` — туда же в проект, `ferry get <устройство> <путь> <каталог>` — сюда (`~/…` — от дома устройства), `ferry pull <устройство>` — правки, сделанные на устройстве.

## Веб-интерфейс (Tauri, CEF, Electron, браузер) — через CDP

Запусти приложение задачей с `--remote-debugging-port=<порт>`, затем `ferry tunnel <устройство> <порт>` — порт устройства станет `127.0.0.1:<порт>` здесь. Дальше Playwright `chromium.connectOverCDP('http://127.0.0.1:<порт>')` (запускать на Node — из Bun CDP не подключается) или MCP поверх CDP. `ferry tunnel` без аргументов — открытые туннели, `--close` — закрыть.

## Нативный интерфейс — как человек

CDP вводит в обход ОС; фокус окон, диалоги, трей и системные окна проверяются настоящим вводом:

```sh
ferry windows win-10                     # окна сверху вниз, * — с фокусом
ferry focus win-10 app                   # вывести окно вперёд, с фокусом (и свёрнутое, и с другого
                                         #   стола): окна задач открываются позади, а --name/--text
                                         #   ищут в окне с фокусом
ferry ui win-10 [<процесс|часть заголовка>]   # элементы окна: роль "имя" #id x,y ширина×высота
ferry click win-10 --name "Сохранить"    # клик в центр элемента по имени (окно с фокусом); '#15' — по #id
ferry text win-10                        # текст окна с фокусом, распознанный с экрана (canvas, игры)
ferry click win-10 --text "Готово"       # клик по распознанному тексту; wait --text — ждать его
ferry shot win-10                        # снимок → печатает путь к PNG; открой его и посмотри
ferry shot win-10 --window app           # само окно, даже закрытое другими: меньше картинка — дешевле;
                                         #   для click прибавь к точке начало окна (ferry его печатает),
                                         #   а клик попадёт в верхнее окно — закрытое сначала ferry focus
ferry shot win-10 --region 0,0,800,600   # часть экрана; к точке на снимке прибавь начало области
ferry click win-10 458 390 [right|double]  # координаты — пиксели снимка
ferry wait win-10 --window "Сохранить как"   # ждать окно вместо sleep; --gone — пока не закроется
ferry wait win-10 --name "Готово" --timeout 60   # ждать элемент; печатает его место
ferry type win-10 'текст'                # юникодом, раскладка не важна
ferry key win-10 ctrl+s enter alt+f4
ferry key win-10 ctrl+= ctrl+- ctrl++   # = и -; plus или + — Shift+= (ANSI)
ferry key win-10 space --for 2           # долгое нажатие
ferry click win-10 300 200 --hold shift  # shift/ctrl/cmd+клик; у drag тоже есть --hold
ferry drag win-10 100 200 400 200        # перетащить: выделение, ползунок, перенос
ferry move win-10 500 300                # навести курсор (подсказки, hover); или --name <имя>
ferry scroll win-10 -3                   # колесо: больше нуля — вверх
ferry clip win-10 [текст]                # буфер обмена: прочитать или положить
ferry rec win-10 6                       # 6 с кадрами → лист-обзор (анимации, мигание)
```

Порядок: `ferry ui` и клик по имени — надёжнее пикселей. Если элементов нет (рисованный интерфейс, игра, canvas) — `ferry text` и `click --text`; текста нет — `ferry shot`, найди место на снимке, `ferry click x y`, проверь новым снимком. Ввод, окна и запись — на Windows и macOS (на маке ferry нужен доступ к «Универсальному доступу» — ошибка скажет, куда идти). «не на экране» в `ferry windows` — свёрнуто или на другом рабочем столе: `ferry focus` вернёт.

## Если что-то не так

- `ferry logs <устройство> [-n 300]` — лог приложения ferry на устройстве (связь, ошибки).
- `ferry crashes <устройство> [<программа>] [--last]` — упало приложение под тестом: когда, и `--last` — исключение и стек последнего падения.
- `ferry info <устройство> --json` — система, железо, диск; в `warnings` — мало места, экран заблокирован и т. п.
- `ferry doctor <устройство>` — хватает ли инструментов и доступа к git-зависимостям для этого проекта.
- Приватные git-зависимости (cargo, bun по ssh): один раз `ferry trust <хост>` на этой машине — устройства будут ходить в git её ключами.
- Устройство не на связи — оно выключено или без сети; подожди или скажи человеку.

## Вежливость

За устройством может работать человек: он видит в трее и по коралловой рамке по краю экрана, что им управляют (рамка горит, пока действие идёт, и 10 с после). Не выключай и не перезагружай (`ferry power`) без просьбы, после себя гаси задачи (`ferry kill`/`ferry stop`), не трогай чужие окна без нужды.

## Локальные сборки ferry

С ferry 0.1.19: `ferry update <цели> --file <пакет>` передаёт подписанный установщик напрямую и ждёт новый процесс с ожидаемой версией (180 с). `.sig` должен лежать рядом; Windows — `ferry_*_x64-setup.exe`, macOS — `ferry.app.tar.gz` с прежним сертификатом и подходящей архитектурой. Пакет той же версии допускается, откат — нет. Для своего мака цель опускается; Windows обновляй с другого устройства, чтобы CLI не блокировал замену своего exe. Перед раскаткой проверь свободные устройства: режим должен быть active. Ошибка/тайм-аут не запускают повторную установку. Перезапуск той же версии не доказывает побайтовое совпадение сборки. Старые узлы сначала обнови обычным способом до 0.1.19.
