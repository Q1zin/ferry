![ferry — разработка и тесты на нескольких устройствах сразу](.github/social-preview.png)

Разработка и тесты на нескольких устройствах сразу: код пишешь здесь, а собираешь, запускаешь и смотришь на экран — на любом связанном устройстве, в том числе на настоящем рабочем столе Windows. На каждом устройстве — приложение ferry; команды идут отсюда через приложение на этой машине. Рассчитан и на человека, и на ИИ-агента: всё — обычные команды с выводом и кодом выхода.

```sh
ferry devices                                   # устройства: на связи ли, путь, роль, режим
ferry run win-10 -- cargo test                  # снимок проекта, затем команда там же в проекте
ferry run all -- bun test                       # на всех узлах сразу; строки с [устройство]
ferry run os:windows --desk -- bunx playwright test --project=live --reporter=line
ferry start win-10 app -- ./target/debug/app.exe --remote-debugging-port=9322
ferry tunnel win-10 9322                        # CDP приложения на узле — здесь, на 127.0.0.1:9322
ferry log win-10 app -f                         # лог задачи; выйдет с её кодом
ferry shot win-10                               # снимок экрана → ~/.ferry/shots/win-10.png
ferry click win-10 458 390                      # настоящий клик ОС в точку снимка
ferry get win-10 playwright-report              # отчёт, логи, сборка — сюда
```

`ferry` без аргументов — полный список команд.

## Начать

1. Поставь приложение ferry на каждое устройство — из [релизов](https://github.com/Q1zin/ferry/releases): `ferry_<версия>_aarch64.dmg` на мак, `ferry_<версия>_x64-setup.exe` на Windows (ставится в профиль пользователя, без прав администратора). Оно живёт в трее и запускается при входе в систему.
2. Свяжи устройства: на новом — «Связать устройство» → «Показать код» (или `ferry pair`), на своём — введи код (`ferry pair 4821-0937`). В одной сети устройство находится само; из другой — вводят ссылку `ferry:<ключ>:<код>`. Связи — только те, что ты сделал сам; убрать — «Забыть устройство» в окне или `ferry forget <устройство>` (только на этом устройстве).
3. Команда `ferry` в терминале — на машине, откуда управляешь: «Настройки» → «Поставить команду ferry». Она едет с приложением и ходит в приложение на этой же машине.
4. Открой «Подключить агента» в приложении или выполни `ferry setup install claude` / `ferry setup install codex`. Нужен установленный CLI выбранного агента. Setup добавляет skill и MCP, сохраняя чужую конфигурацию; затем перезапусти сессию агента. `ferry setup status` проверяет настройку, `ferry setup smoke local` запускает первую безопасную фоновую проверку. Результаты — во вкладке «Прогоны» и `ferry check list`. Прежний `ferry skill` остаётся для установки только Claude skill.

## Прогоны, агенты и веб-панель (0.1.24)

- **Подключение Claude Code и Codex:** мастер настройки, skill + MCP, безопасная первая проверка; `ferry init --template smoke|tauri|electron|web` создаёт профиль нового проекта.
- **Центр прогонов:** фильтры, длительности, этапы, testcase, артефакты и ZIP-отчёт. `check compare BASE CANDIDATE` показывает регрессии только для сопоставимых полных результатов.
- **Очередь:** `queue add PROFILE --file ferry.checks.json --devices all --wait 600` ждёт подходящее устройство и сохраняет назначение до запуска. Неясный исход не переносится вслепую.
- **Повторяемые GUI-сценарии:** `workflow validate/run` исполняет JSON-шаги с локаторами и проверяемыми изменениями только в окне своего живого запуска.
- **Живой экран и MP4:** просмотр основного дисплея до 10 кадров/с, явное включение управления; `capture` и поле `record` профиля сохраняют своё окно с временными метками. Для MP4 нужен FFmpeg 5.1+ с libx264 на пульте.
- **Локальная панель:** `ferry server --port 8080` открывает тот же интерфейс в браузере по ссылке с токеном. Только loopback, по умолчанию просмотр и экспорт; `--allow-actions` включает resume/cancel существующих проверок.

Команды, ограничения и готовые JSON-примеры — в [руководстве по работе агента](docs/agent-workflows.md).

## Цели

`<цели>` в командах — имя устройства (или начало ключа), несколько через запятую, `all` — все на связи, которые принимают команды, `os:windows` / `os:macos` — по системе. На нескольких целях команда идёт параллельно, строки вывода подписаны `[устройство]`, в конце — сводка кодов, а код выхода — первый ненулевой. Устройство, отказавшее по режиму или роли, отвечает кодом 75.

## Команды и проект

`ferry run <цели> [--desk] [--no-sync] [--home] [--shell <имя>] -- <команда>` сначала кладёт на устройство снимок проекта, затем выполняет команду в том же подкаталоге проекта (вне репозитория или с `--home` — в домашнем каталоге устройства, без снимка). Команды на устройстве находят `ferry` рядом с приложением, даже если его не ставили в PATH. Вывод — потоком, код выхода — устройства. Прервал CLI (Ctrl-C, таймаут) — команда на устройстве останавливается.

Оболочка выбирается для каждого `run` или `start`: `--shell default|bash|powershell|cmd`. По умолчанию на Windows — Git Bash, на macOS — login-шелл пользователя, как раньше. PowerShell и cmd доступны только на Windows и запускаются напрямую, без Bash; `powershell` — Windows PowerShell без профиля. У фоновой задачи выбор сохраняется до её завершения. Явный выбор требует ferry 0.1.18 на пульте и устройстве; служебная синхронизация продолжает использовать прежнюю оболочку.

```sh
ferry run win-10 --home --shell powershell -- 'Get-Location; $PSVersionTable.PSVersion'
ferry run win-10 --home --shell cmd -- 'ver & echo %USERPROFILE%'
ferry start win-10 build --shell powershell -- 'cargo build; exit $LASTEXITCODE'
```

В PowerShell при запуске внешних программ используй `exit $LASTEXITCODE`, если нужен их точный код завершения. Вывод передаётся без перекодирования: у cmd и некоторых системных программ Windows он может быть в OEM-кодировке. Для команд с русским текстом предпочтителен PowerShell с UTF-8.

- **Снимок** — рабочее дерево как есть: с незакоммиченным и новыми файлами. Он коммитится вне веток и без родителя: ветка и индекс здесь не меняются, на устройство в первый раз едет только дерево, дальше — только разница (git-бандл). Проект живёт на устройстве в `~/ferry/<имя репозитория>`. Файлы из `.gitignore` (`target/`, `node_modules/`) не ездят — кроме перечисленных в `files` настроек проекта.
- **Правки на устройстве** не теряются: если там правили поверх снимка, перед перезаписью они сохраняются патчем в `~/.ferry/saved/`. `ferry pull <устройство>` применяет их к рабочему дереву здесь.
- **`--desk`** — команде нужен рабочий стол (окна, GUI-тесты): в режиме «не трогать рабочий стол» такие отклоняются. Команды идут в сессии пользователя, где живёт приложение, — окна видны, ввод работает.
- **Бронь стола** — окна и ввод устройства у одной сессии за раз, иначе клики двух агентов перемешаются. Сессия — `FERRY_AGENT`, иначе нативный процесс Claude Code, из которого вызван ferry (macOS, Linux, Windows), иначе терминал. `--desk`, `start` и ввод сами занимают стол на 3 мин и продлевают бронь, `run --desk` держит её до конца команды; у другой сессии они отклоняются (код 75) — с тем, кто занял и на сколько. Смотреть (`shot`, `windows`, `ui`, `text`) и `run` без `--desk` можно всем. `ferry desk <устройство>` — кто занял; `take [<минут>]` — надольше (по умолчанию 30); `free` — снять свою, `free --force` — чужую. Когда процесс `claude:<pid>` завершается, пульт снимает его бронь при ближайшей проверке (раз в 5 с); при обрыве связи повторяет попытку до истечения брони. Произвольные имена `FERRY_AGENT` освобождаются вручную или по сроку. После перезапуска пульта уже выданные брони живут до своего срока.
- `ferry sync <цели>` — только снимок; `ferry put <цели> <файл>…` — файлы отсюда на то же место в проекте; `ferry get <устройство> <путь> [куда]` — файл или каталог оттуда (`~/…` — от дома устройства).
- `ferry doctor <цели>` — готово ли устройство собирать этот проект: инструменты (свои и из `tools` настроек проекта), доступ к git-зависимостям, файлы из `files`.

## Результаты для агента (0.1.21)

```sh
ferry select --os windows --shell powershell --tool cargo --desktop
ferry observe WIN-11-2 --window my-app --ocr
ferry artifacts WIN-11-2 build --add reports/junit.xml
ferry artifacts WIN-11-2 build --add screenshots/failure.png
ferry tests WIN-11-2 build --junit '<artifact_id>'
ferry runs WIN-11-2 build
ferry result WIN-11-2 build --run '<run_id>'
ferry artifacts WIN-11-2 build --run '<run_id>' --get '<artifact_id>' --dest ./evidence
```

`select` возвращает подходящие связанные устройства и конкретные причины отказа остальных. Инструменты проверяются в выбранной оболочке; `--desktop` также требует свободной брони, разрешённого и разблокированного рабочего стола. Команда не резервирует устройство и не определяет, сидит ли за ним человек. Перед GUI-прогоном нужен `desk take`. Без `--desktop` допускаются фоновые `run` на устройствах в режиме «не трогать рабочий стол», но `start` требует active. Версии и зависимости проекта проверяет `doctor`.

`observe` одним запросом получает выбранное окно, текущий фокус, ограниченное дерево Accessibility/UI Automation и PNG. `--ocr` добавляет распознанный текст того же снимка. Фокус не меняется; права, режим и бронь сохраняют силу. Ответ содержит `warnings`, признаки обрезки и `changed_during_capture`: если окно переместилось/исчезло или изменился фокус, наблюдение нужно повторить. Это последовательный сбор, не атомарный снимок состояния приложения. Дерево — до 24 КиБ; OCR — до 200 строк, PNG — до 8 МиБ. Координаты дерева — в пикселях рабочего стола, OCR — в пикселях PNG; начало окна — `window.rect`. Без устройства команда работает локально. MCP возвращает картинку и структурированный JSON.

Новый старт сохраняет предыдущую задачу в `~/.ferry/runs/<имя>/<run_id>`. `runs` показывает последние 100 запусков, общее количество и флаг обрезки. `result --run` читает конкретный запуск без ожидания. `artifacts --add` делает независимую копию **явно указанного файла на устройстве** (относительный путь — от рабочего каталога задачи). Файл лучше прикреплять после завершения записи, с `--run`, чтобы зафиксировать нужный запуск. Предел — 64 МиБ на файл, 256 файлов / 512 МиБ на запуск; каталоги и ссылки отклоняются. История автоматически не очищается: её размер нужно контролировать.

`artifacts` возвращает идентификаторы, размеры и пути; полный лог доступен как артефакт `log`. `--get` скачивает в `<dest>/<run_id>/<artifact_id>/`, не перезаписывая существующий каталог. Скриншот `observe` можно явно прикрепить как файл на той машине, где он сохранён; автоматической привязки снимков к задачам пока нет.

`tests --junit <artifact_id>` читает прикреплённый JUnit XML (до 16 МиБ): фактическое количество testcase, прошедшие/упавшие/ошибочные/пропущенные, сумму времени testcase и до 50 падений. Имя, класс, файл, строка, сообщение и стек берутся из отчёта. XML не исполняется, DTD отклоняются. Падения, пустой отчёт и несоответствие счётчиков дают код 1. Сводка не подменяет код завершения самой задачи: проверяй и `result`. Все новые команды возвращают JSON и MCP `structuredContent`; на обеих сторонах нужна 0.1.21.

## Фоновые задачи и туннели

Для агента удобнее получать ограниченный результат задачи (с ferry 0.1.20 на обеих сторонах):

```sh
ferry start WIN-11-2 test-agent --home --shell powershell -- 'Write-Output "проверка"; exit 7'
ferry result WIN-11-2 test-agent --wait 30
ferry result WIN-11-2 test-agent --cursor '<cursor из прошлого ответа>' --wait 30
ferry result local-test --max-bytes 4096  # задача этой машины
```

`result` выдаёт один JSON: `device`, `name`, `state` (`running`, `succeeded`, `failed`, `killed`, `lost`), `exit_code`, `started`, `cwd`, `run_id`, `log`, `cursor`, `more`, `omitted_bytes`. Код CLI — код завершившейся задачи; `killed`/`lost` дают 1, `running` даёт 0 **и не означает успех задачи**. Ошибки запроса (нет задачи, обрыв связи, старый курсор) идут в stderr с ненулевым кодом. MCP дополнительно возвращает этот JSON в `structuredContent`, сохраняя текстовый ответ.

Без курсора читается **хвост**, по умолчанию последние 16 КиБ исходных байтов лога; `--max-bytes` задаёт от 4 до 65536. `omitted_bytes` показывает пропущенное начало. С курсором читается следующий фрагмент без повторов; если `more: true`, есть непрочитанные байты. Курсор относится к конкретному запуску: после перезапуска задачи старый курсор отклоняется. Передавай его целиком, не вычисляй сам. Границы UTF-8 не разрываются, некорректные байты заменяются символом `�` (для Windows cmd с OEM-кодировкой лучше PowerShell с UTF-8).

`--wait 30` без курсора ждёт завершения до 30 секунд; с курсором — новых данных или завершения. Максимум — 60 секунд. По окончании ожидания живая задача возвращается как `running` и продолжает работать. Чтение разрешено в режиме «не трогать рабочий стол», но удалённое чтение в отключённом режиме запрещено. Полный лог остаётся на устройстве: `ferry get WIN-11-2 '~/.ferry/jobs/test-agent/log' ./evidence`. С 0.1.21 повторный `start` архивирует предыдущий запуск вместе с логом и прикреплёнными файлами; на старых версиях прежний лог заменяется.

С 0.1.18 новые фоновые задачи Windows запускают надсмотрщика из `~/.ferry/runners/<сборка>/ferry-job.exe`, вместе с его DLL. Установка следующей версии не завершает эти процессы и не заменяет их файлы. Уже работающие задачи старой версии нужно сначала завершить или перезапустить после обновления. Копии старых сборок пока сохраняются: не удаляй их, пока соответствующие задачи работают. Новые обращения к git-релею после перезапуска ferry используют свежие порт и токен из приватного файла `~/.ferry/relays/<устройство-заказчик>`. Уже открытое SSH-соединение может оборваться: такую git-команду нужно повторить. Это работает для задач, запущенных новой сборкой; старые задачи с прежним shim нужно перезапустить.

`run` ждёт конца команды. Для того, что живёт дальше — запущенное приложение, dev-сервер, долгая сборка, — фоновая задача:

```sh
ferry start win-10 app -- ./src-tauri/target/debug/logarithmica.exe --remote-debugging-port=9322
ferry jobs win-10                 # работает / завершилась, код N / остановлена
ferry log win-10 app -f           # следить за логом; выйдет с кодом задачи — так можно ждать сборку
ferry wait win-10 --log app "Listening on"   # ждать строку в логе (печатает её); вышла раньше — код 1
ferry wait win-10 --port 9322     # ждать, пока порт откроется (127.0.0.1 или ::1); --gone — закроется
ferry kill win-10 app             # то же имя в start — перезапуск
ferry stop win-10                 # снять всё: команды и задачи
```

`log -f` и `wait --log` переживают обрыв связи (перезагрузка, сон, смена сети): ждут, пока устройство вернётся (до 15 мин), и продолжают с того же места.

Задача идёт на рабочем столе устройства под своим процессом-надсмотрщиком (это exe приложения): переживает перезапуск приложения, лог и код выхода лежат в `~/.ferry/jobs/<имя>/` на устройстве.

Туннель делает порт устройства локальным — тем же номером, потому что CDP отдаёт ws-адрес со своим портом. На устройстве он идёт на `127.0.0.1`, а если там никого — на `::1` (Vite на маке слушает только его). Туннель держит приложение здесь, пока не закроешь:

```sh
ferry tunnel win-10 9322           # 127.0.0.1:9322 здесь → 9322 на устройстве
ferry tunnel                       # открытые туннели
ferry tunnel win-10 9322 --close
```

Так Playwright (`chromium.connectOverCDP('http://127.0.0.1:9322')`) и MCP `cef` работают с приложением на устройстве как с локальным:

```sh
claude mcp add cef-win-10 -- npx -y @playwright/mcp@0.0.83 --cdp-endpoint http://127.0.0.1:9322
```

Playwright из Bun через CDP не подключается (WebSocket так и не открывается) — запускай его на Node.

## Экран устройства: окна, ввод, запись

Ввод через CDP идёт в рендерер в обход ОС — нативные баги фокуса так не воспроизвести. Эти команды работают как человек за клавиатурой: события ввода и окна самой ОС — `SendInput` на Windows, CGEvent на маке. Координаты — пиксели снимка `ferry shot` (на Retina — настоящие пиксели, вдвое больше точек), поэтому цикл «снимок → нашёл кнопку → клик → снимок» работает напрямую.

На маке снимкам нужен доступ к записи экрана, вводу — к «Универсальному доступу». Страница «Разрешения» в окне ferry показывает оба и открывается сама, пока чего-то не хватает: «Выдать» — раздел «Системных настроек», где включить ferry; запись экрана macOS применяет после перезапуска ferry (кнопка там же). Выдаются один раз: сборки из релизов подписаны одним сертификатом, и обновления доступы не сбрасывают. Лист-обзор записи — пока только на Windows; несколько мониторов на маке не поддержаны: снимок и координаты — главного дисплея.

```sh
ferry windows win-10                     # окна сверху вниз по z-порядку; * — у кого фокус; свёрнутые — «не на экране»
ferry focus win-10 notepad               # вывести окно вперёд, с фокусом — и свёрнутое, и с другого рабочего стола
ferry ui win-10                          # элементы окна с фокусом: роль, «имя», #id, место
ferry click win-10 --name "Сохранить"    # клик по имени элемента
ferry text win-10                        # текст окна с фокусом, распознанный с экрана: «текст» и место
ferry click win-10 --text "Готово"       # клик по тексту на экране — canvas, WebGL, игры без элементов
ferry click win-10 458 390 [right|double]
ferry move win-10 458 390                # навести (hover)
ferry scroll win-10 -3                   # колесо: больше нуля — вверх
ferry type win-10 'Привет, мир'          # юникодом: раскладка не важна
ferry key win-10 ctrl+a delete alt+f4    # комбинации по порядку
ferry key win-10 ctrl+= ctrl+- ctrl++   # = и -; plus или + — Shift+= (ANSI)
ferry key win-10 space --for 2           # держать 2 с и отпустить (до 60 с)
ferry click win-10 300 200 --hold shift  # клик с зажатыми клавишами: shift/ctrl/cmd+клик
ferry drag win-10 100 200 400 200        # перетащить левой кнопкой (тоже с --hold)
ferry clip win-10                        # буфер обмена устройства; ferry clip win-10 'текст' — положить
ferry shot win-10 --window notepad       # само окно (процесс или часть заголовка), даже закрытое другими
ferry wait win-10 --window "Сохранить как"   # ждать окно (или --gone — пока не закроется), до 30 с
ferry wait win-10 --name "Готово" --timeout 60   # ждать элемент окна с фокусом
ferry wait win-10 --text "Готово"        # ждать текст на экране (canvas)
ferry shot win-10 --region 0,0,800,600   # область x,y,ширина,высота
ferry rec win-10 6 [4]                   # 6 с по 4 кадра → ~/.ferry/recs/<устройство>-<время>/
```

Клик по пикселям хрупок (другой масштаб экрана — и кнопка уехала). Надёжнее — по имени элемента: `ferry ui win-10 [<процесс|часть заголовка>]` печатает элементы окна (UI Automation на Windows, Accessibility на маке: роль, «имя», #id, место), `ferry click win-10 --name "Сохранить"` кликает в центр элемента с этим именем в окне с фокусом, `--name '#15'` — по #id для безымянных элементов (`move --name` — навести). Окна, запущенные задачей ferry, Windows открывает позади и без фокуса, а мак — бывает, что на другом рабочем столе, — сначала `ferry focus`. Веб-интерфейсы (WebView2, Chromium) тоже отдают свои кнопки и поля. У canvas, WebGL и игр элементов нет — тогда текст на экране: `ferry text` распознаёт область окна с фокусом (Vision на маке, Windows.Media.Ocr на Windows — оба встроены в систему; на Windows ищут сразу язык пользователя и английский), `click --text`, `move --text` и `wait --text` ищут в ней текст без учёта регистра: сначала строку целиком, потом часть строки.

На macOS при ошибке Vision или отсутствии ответа за 10 с ferry повторяет распознавание на CPU. Обе попытки делят общий лимит 20 с. Если CPU справился, следующие запросы сразу используют его до перезапуска ferry; пустой результат сам по себе не включает этот режим. На macOS 14+ устройство вычислений задаётся явно для каждого этапа Vision, на более ранних системах — через `usesCPUOnly`. Если обе попытки не удались, ошибка содержит обе причины.

`rec` печатает путь к `sheet.png` — до 12 равномерно выбранных кадров с отметкой времени на одном листе. Есть `ffmpeg` здесь — рядом появится и `video.mp4`. Чего ввод не может: окна, запущенные от администратора, заблокированный экран и окно UAC.

## Приватные git-зависимости: релей

Ключ от GitLab/GitHub есть только у тебя, а `cargo`, `bun`, `npm` и сам `git` на устройстве достают приватные репозитории по SSH:

```sh
ferry trust git.logarithmica.ru     # один раз здесь; ferry trust — список
```

Команды, которые ты запускаешь на устройстве, получают `GIT_SSH_COMMAND='<exe приложения> ssh'`. Для доверенного хоста это не ходит в сеть само: сессия уходит в приложение устройства и по связи ferry — к тебе, а здесь выполняется твоим ssh. Ключ отсюда не уходит.

- **Только чтение**: `git-upload-pack` и `git-upload-archive`. Push с устройства отклоняется — скомпрометированное устройство не запушит от твоего имени.
- **Только доверенные хосты** из `~/.ferry/trust` здесь; аргументы проверяются так, чтобы ни одно поле не стало опцией ssh.
- Недоверенные хосты — обычный ssh устройства. cargo по умолчанию ходит в git мимо `GIT_SSH_COMMAND`, поэтому ferry ставит ему `CARGO_NET_GIT_FETCH_WITH_CLI=true`.

## Роль и режим

- **Роль** — что устройство делает: узел (принимает команды), пульт (только управляет другими) или оба. Меняется с любого связанного устройства: `ferry role win-10 node` или в окне.
- **Режим** выбирает только человек за устройством — в трее или в окне:

| Режим | Иконка | Что значит |
|---|---|---|
| `active` — работает | коралловая | обычная работа |
| `no-desktop` — не трогать рабочий стол | фиолетовая, как «Не беспокоить» | `--desk`, задачи, снимки и ввод отклоняются (код 75), сборки идут |
| `paused` — отключён от других устройств | серое кольцо | ничего не выполняется, роль и имя издалека не меняются |

Пока с другого устройства вводят, снимают экран или запускают окна, иконка ferry здесь белая, а подсказка говорит, кто управляет; «Остановить управление» в её меню включает «не трогать рабочий стол». Иконка горит до конца действия и ещё 10 с после, как рамка. По краю экрана — коралловая рамка с надписью, кто управляет: горит, пока действие идёт (`run --desk` — до конца команды), и ещё 10 с после; бронь её не держит. Клики идут сквозь неё, фокус она не берёт, на снимках и записи экрана её нет. Всё, что связанные устройства делали на этом, — в журнале на его странице в окне и в `~/.ferry/logs/ferry.log` (набранный текст туда не попадает).

Windows может спрятать новую иконку под «^» у часов — перетащи её на панель один раз.

## Связь

- **iroh**: устройство адресуется ключом, а не IP — сменился адрес, VPN, другая сеть, связь та же. Шифрование сквозное, связанные устройства доверяют друг другу.
- В одной сети — напрямую. Поиск соседей — mDNS только на LAN-интерфейсах: у VPN свой маршрут на multicast. Из разных сетей — через публичные relay n0 с пробивкой NAT до прямого пути.
- DNS — публичные серверы через HTTPS и системный резолвер одновременно, ответ — первый успешный: с VPN системный DNS ломается, в корпоративной сети наружу закрыт любой DNS, кроме своего.
- UDP-порт 47760: после перезапуска устройство на том же адресе, и остальные снова достают до него за секунды. Занят — любой свободный.
- Устройство пропало — видно через ~12 с. Состояние (режим, роль, путь) приходит само, без опроса.

Связывание: код из 8 цифр, 10 минут, 5 попыток. В сеть код не уходит (SPAKE2): подставное устройство его не узнает.

## Приложение

Одно на любом устройстве (macOS, Windows): в трее — режим этого устройства, «Открыть ferry», «Связать устройство…», «Выйти». Закрытое окно ferry не останавливает.

- **Устройства** — это и связанные: путь (напрямую или через relay), задержка, роль, режим.
- **Страница устройства**: «Обзор» — роль, режим, имя, свойства (система, железо, диск, питание) и питание (Windows); «Экран» — снимок, живой экран, клики по снимку уходят на устройство, текст и клавиши; «Задачи» — список, лог, запуск и остановка.
- **Связать устройство** — показать код или ввести код/ссылку; рядом видно устройства, которые ждут связывания.
- **Настройки** — запуск при входе в систему, команда `ferry` в терминале, обновления.

Ключ устройства, имя, роль и связанные устройства — в `~/.ferry` (`key`, `device.json`); `~/.ferry/app` — порт и токен для CLI.

Лог приложения — `~/.ferry/logs/ferry.log`, туда же — паника, если приложение упало. Что-то не так на устройстве — его хвост отсюда: `ferry logs win-10 [-n 300]`; `ferry logs` без цели — лог этой машины.

Свойства устройства — `ferry info win-10 [--json]`: система, железо, диск, экран; в `warnings` — мало места, экран заблокирован и т. п. Питание Windows — `ferry power win-10 reboot|sleep|shutdown|cancel` (reboot и shutdown — через 10 с).

Падения программ на устройстве — `ferry crashes win-10 [<программа>]`: свежие сверху; `--last` — разбор последнего (исключение, модуль, стек). На маке — отчёты `~/Library/Logs/DiagnosticReports/*.ips`, на Windows — журнал «Приложение» (файлы WER в ProgramData пользователю не прочесть).

## Обновления

Новые версии — релизы на GitHub. Приложение проверяет их при запуске: есть новая — у «Настройки» в окне появится «есть <версия>». Ставит человек — в настройках — или ты отсюда:

```sh
ferry update                      # эта машина
ferry update all                  # все связанные на связи, и пульты
```

Устройство скачивает пакет, отвечает и ставит его: Windows запускает приложение после установки сама, мак — перезапускает. Через несколько секунд устройство снова на связи с новой версией. Пакет подписан ключом ferry, неподписанный приложение не поставит. Устройство в режиме «отключён» издалека не обновляется.

Локальную сборку можно поставить без GitHub, тега и опубликованного релиза (на пульте и получателе нужен ferry **0.1.19**):

```sh
ferry update WIN-11-2 --file target/x86_64-pc-windows-gnu/release/bundle/nsis/ferry_0.1.19_x64-setup.exe
ferry update --file target/release/bundle/macos/ferry.app.tar.gz
ferry update os:windows --file /path/to/ferry_0.1.19_x64-setup.exe
```

Рядом с пакетом нужен созданный Tauri файл `.sig`. Подпись и версия проверяются **на получателе** встроенным ключом updater; имя пакета берётся из подписанного комментария. Принимаются более новые версии и новые сборки той же версии, откат отклоняется. Пакет передаётся напрямую по существующей связи, без синхронизации проекта; максимум — 512 МиБ. На маке перед установкой дополнительно проверяются архитектура обоих бинарников, целостность подписи macOS и совпадение сертификата с установленным ferry — чужая архитектура или другая подпись отклоняются, чтобы сохранить запуск и разрешения macOS. Windows обновляй с другого устройства: работающий установленный локальный CLI блокирует замену `ferry.exe`.

Команда показывает передачу и проверку подписи, затем до 180 секунд ждёт **новый процесс** с версией пакета. Успех означает подтверждённый перезапуск и связь; для двух сборок одной версии это не побайтовая проверка установленного приложения. Ошибка установки возвращается через статус, отсутствие связи — ненулевым кодом без автоматической повторной установки. Локальная установка разрешена только в активном режиме, в том числе на пультах; перед раскаткой проверь, что устройством никто не пользуется. Старым версиям сначала нужна обычная установка 0.1.19, после неё доступна эта команда.

Устройства разных версий работают вместе. Команда, которой устройство ещё не знает, не уходит на него, а сразу отвечает: «на win-10 ferry 0.1.2, а ferry logs — с 0.1.3: обнови его — ferry update win-10».

## Релиз

Версия одна — `version` в корневом `Cargo.toml`; после релиза её сразу поднимают до следующей, и новые запросы протокола помечают ей (`Device::need`). Сборки релиза подписываются ключом обновлений: приватный — у того, кто выпускает (`~/.tauri/ferry.key`, в GitHub — секрет `TAURI_SIGNING_PRIVATE_KEY`), публичный — в `tauri.conf.json`. Потерян приватный ключ — установленные копии новых версий не примут, их придётся переставить руками.

Релиз собирает GitHub Actions (`.github/workflows/release.yml`) по тегу с той же версией:

```sh
git tag v<версия> && git push origin v<версия>
```

Сборки для macOS и Windows, пакеты обновления и `latest.json` попадают в черновик релиза — устройства увидят новую версию, когда его опубликуют. Без тега (Actions → release → Run workflow) — только сборка, файлы в артефактах прогона.

То же локально, без Actions:

```sh
cd apps/ferry
export TAURI_SIGNING_PRIVATE_KEY="$HOME/.tauri/ferry.key" TAURI_SIGNING_PRIVATE_KEY_PASSWORD=
bun run release:mac                         # dmg и пакет обновления для мака (Apple Silicon)
bun run release:windows                     # setup.exe (brew install mingw-w64 nsis)
bun run release:files                       # → target/release-v<версия>/: установщики, пакеты, latest.json
gh release create v<версия> ../../target/release-v<версия>/*
```

Приложение ищет `latest.json` последнего релиза, поэтому новая версия доходит до устройств, как только релиз опубликован. Мак подписан своим самоподписанным сертификатом (`apps/ferry/src-tauri/macos-signing.pem`; ключ — у того, кто выпускает, в `~/.tauri/ferry-macos.p12`, в GitHub — секреты `MACOS_CERTIFICATE` и `MACOS_CERTIFICATE_PASSWORD`). Требование к подписи у всех сборок одно, поэтому доступы macOS переживают обновления; локальные сборки без явно выбранного сертификата — ad-hoc. Для установки локальной сборки поверх существующей импортируй тот же сертификат, доверь ему только подпись кода и передай `APPLE_SIGNING_IDENTITY=ferry` при `bun run release:mac`. Перед заменой приложения проверь `codesign --verify --deep --strict` и совпадение `codesign -d -r-` у старого и нового приложения, а также CLI внутри него. Тег и публикация для такой установки не нужны. Нотаризации нет: скачанное из браузера приложение macOS в первый раз не запустит — «Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть». Обновления это не затрагивает.

### Устойчивые проверки и жизненный цикл приложения (0.1.23)

`check` сохраняет ID операции, профиль и точный снимок исходников **до запуска**. Можно отключить
CLI и позднее получить результат без повторного запуска уже выполненных этапов.

```sh
ferry check rust --file ferry.checks.example.json --devices local,WIN-11-2 --parallel 2 --id rust-review --detach
ferry check status rust-review
ferry check resume rust-review
ferry check collect rust-review
ferry check cancel rust-review
```

Повторный ID с другим профилем, снимком или целями отклоняется. `status` только читает;
`resume` продолжает незавершённые этапы, `collect` только собирает уже запущенное и не создаёт
новых фаз. `cancel` сохраняет отмену,
останавливает свои точные run ID и запрещает запоздавший запуск с теми же request ID.
Фоновый сборщик не зависит от вызвавшего его терминала. Если сборщик аварийно завершился,
`status` покажет `interrupted`; нужен `resume`, автоматического watchdog нет. Недоступное
устройство не считается очищенным: повтори `resume`/`cancel` после восстановления связи.

Профили — исполняемые команды знакомого проекта в `ferry.checks.json`; пример —
[`ferry.checks.example.json`](ferry.checks.example.json). `platforms.{macos,windows,all}`:

- `build` — необязательная сборка, обязана завершиться успешно;
- `launch` — необязательное приложение или сервер, который живёт во время проверки;
- `command` — тестовая команда, обязана завершиться с кодом 0;
- `shell`: default/bash/powershell/cmd; `tools` — команды, необходимые в этой оболочке.

Общие поля профиля: `timeout` 1–3600 секунд на работу цели, `headless` (по умолчанию false),
`junit`, до 32 `artifacts`, `window` для диагностического снимка своего окна. Команды пишут
отчёты в уникальный `{output}`; пути `junit`/`artifacts` относительны ему. Добавь `.ferry-checks/`
в `.gitignore`. `{run}` — уникальный маркер конкретного запуска.

У `launch` обязательно условие готовности: `ready_log`, `ready_port`, `ready_window` или
`ready_http`. Окно ищется по точному заголовку среди процессов запущенной задачи.
`ready_http: {"port": 9322, "path": "/ready", "status": 200, "contains": "{run}"}` проверяет
loopback HTTP и уникальный маркер в теле ответа; приложение должно получить `{run}` через
команду `launch`. Открытый порт сам по себе не доказывает, что отвечает нужный процесс.
После теста ferry собирает файлы и диагностику, затем завершает своё приложение.

В git-проекте профили с `build`/`launch` автоматически используют отдельную копию рабочего
дерева, включая незакоммиченные изменения. Для остальных есть `--isolated`. `--home` работает
в домашнем каталоге, `--no-sync` — в уже подготовленной копии; с изоляцией они несовместимы.
Цели: `local`, имена через запятую, `all`, `os:windows`/`os:macos`; параллелизм 1–8.

Headless-задачи не занимают стол; на устройстве допускаются две одновременно. GUI требует
режим active и бронь. Допуск и проверка занятого workspace выполняются на устройстве под
блокировкой: конфликт даёт явный отказ. Автоматического переноса на другое устройство при
неясном исходе запуска нет. Режим и запреты пользователя действуют и при `all`; наличие
свободного слота не означает отсутствие человека.

Успех — только `state: succeeded` всей матрицы: успешные команды, готовность, все обещанные
файлы, непустой корректный JUnit без падений и завершённая уборка. `running`, `interrupted`,
`incomplete`, `unavailable` не являются успехом. Журнал и отчёты — `~/.ferry/checks/<id>/`.

### Сессии, точные запуски и изолированные исходники

```sh
ferry session begin review --pid <PID_агента> --ttl 3600
ferry start WIN-11-2 app --session review --request review-app --timeout 600 --headless --home -- 'node server.js'
ferry start-status WIN-11-2 review-app
ferry tunnel WIN-11-2 9322 --session review
ferry session renew review --ttl 3600
ferry session end review
```

`session begin` возвращает `agent:<id>`; PID необязателен. Завершение PID, истечение TTL или
`session end` заканчивают сессию. Управляемые задачи и туннели привязаны к ней; `--keep`
оставляет конкретный ресурс. `--timeout` 1–86400 с ограничивает жизнь задачи независимо от
сессии, включая сохранённые `--keep` задачи. Уборка выполняется работающим приложением-пультом
и повторяется после возвращения устройства в сеть. Это не гарантия немедленной остановки
при выключенном пульте: для жёсткого срока задавай `--timeout`.

`start --request` возвращает JSON с неизменным `run_id`. Повтор того же запроса возвращает
старую квитанцию; другие параметры с тем же ID отклоняются. После ошибки связи используй
`start-status`, не новый ID. `--headless` выбирает фоновый ресурс; без него требуется стол.
Новые опции требуют 0.1.23 с обеих сторон. При обнаруженной сессии Claude одиночные start/tunnel
автоматически управляемые. Множественный start в такой сессии заменяй на check. В обычном
терминале старый start без новых опций сохраняет перезапуск по имени; для привязки другой
нейросети зарегистрируй session и передай --session.

```sh
ferry workspace create WIN-11-2 --id review-copy > workspace.json
ferry start WIN-11-2 test --workspace workspace.json --request review-test --headless -- 'cargo test'
ferry workspace diff workspace.json
ferry workspace apply workspace.json --token '<preview_token>'
```

Workspace — отдельный каталог `~/ferry/<проект>--<id>` с базовым git tree и commit.
`start` с новыми опциями из git автоматически создаёт такую копию; `--workspace` позволяет
продолжить подготовленную. Метаданные запуска различают исходный снимок и фактическое рабочее
дерево на момент старта. Это отпечаток git-содержимого, не архив секретов или зависимостей.
`diff` сохраняет patch и показывает проверку применимости к исходному проекту; `apply`
требует свежий token. Изменение исходников или patch отменяет preview. Конфликтующие правки
не перезаписываются. Храни manifest до завершения работы; копии не удаляются автоматически.

### Диагностика и место на диске

```sh
ferry diagnose WIN-11-2 app --run '<run_id>' --bundle --artifact log --artifact '<artifact_id>'
ferry history WIN-11-2 app --pin '<run_id>'
ferry history WIN-11-2 app --older-than 14 --max-bytes 536870912
ferry storage WIN-11-2
ferry storage WIN-11-2 --kind caches --only '<entry_id>' --older-than 7
ferry storage WIN-11-2 --kind caches --only '<entry_id>' --older-than 7 --apply '<preview_token>'
```

`diagnose` сохраняет `~/.ferry/diagnostics/…/report.json`: результат, ограниченный лог,
артефакты, JUnit с `--junit`, команду, оболочку, cwd, исходники и временную шкалу запуска.
Версии инструментов измеряются сейчас в оболочке запуска и помечаются временем; это не
утверждение о версиях во время исторического запуска. Снимок берётся только с явно указанным
`--window`. Отчёт падения по фильтру окна не доказывает связь с конкретным run.

`--bundle` копирует файлы в переносимый пакет с относительными путями. Повторяемый `--artifact`
выбирает точные ID, без него берутся все перечисленные файлы. Пределы: 32 файла, 64 МиБ на файл,
128 МиБ суммарно. Неизвестный ID, меняющийся лог работающей задачи, превышение предела или
ошибка скачивания дают явный неполный пакет и код 1, а не тихую потерю доказательств.

`history` очищает только архивы одной задачи: текущий и закреплённые не удаляются. `storage`
считает логические байты проектов, изолированных копий, кешей, задач, снимков, записей,
отчётов и runners. Категории очистки: `caches`, `outputs`, `shots`, `recordings`, `checks`,
`diagnostics`, `runners`, `questions`, `observations`. Исходники, архивы задач и квитанции
запусков через `storage` не удаляются. Для кешей нужны git-ignore и отсутствие отслеживаемых
файлов; ссылки не обходятся. Активная работа и свежие данные защищены. Учёт не равен свободному
месту файловой системы (разреженные файлы, сжатие и общие блоки учитываются логически).

Без `--apply` очистка — только preview. Список, размеры, времена изменения и параметры
привязаны к token; любое изменение требует нового preview. `--only` ограничивает удаление
одной записью. Останови использующие кеш внешние программы: ferry знает о своих задачах,
но не может гарантировать отсутствие сторонней сборки. Автоматической очистки нет.

### Структурированное наблюдение и проверяемый GUI-шаг

```sh
ferry observe WIN-11-2 --window 'My test app' --structured --no-screenshot > observe.json
ferry observe WIN-11-2 --window 'My test app' --since observe.json
ferry observe WIN-11-2 --window 'My test app' --element '{"role":"button","name":"Save"}'
ferry act WIN-11-2 --from observe.json --click-locator '{"role":"button","name":"Save"}' --expect-json '{"locator":{"name":"Saved"},"property":"exists"}' --dry-run
```

`--structured` возвращает AX/UIA-элементы: role/name/id/parent/rect и доступные value,
enabled/focused/checked/selected. Значения защищённых полей скрыты; отсутствие свойства
остаётся неизвестностью. Locator сопоставляет точные role/name/id, необязательный `within`
ограничивает родительский контейнер. `--element`/`--subtree` сокращают ответ; `--since`
возвращает добавленные/удалённые/изменённые элементы и `snapshot_file` для следующего шага.
Дерево ограничено; усечённое или изменившееся во время сбора не подтверждает действие.

`act` проверяет своё окно, процесс, фокус, геометрию, единственную цель и её предков перед
одним вводом. Постороннее изменение другого элемента не инвалидирует цель. Наблюдение должно
быть свежее 120 с. Для ввода текста требуется `--target '<locator>'` уже сфокусированного поля.
`--expect-json` проверяет exists/absent/value/enabled/focused/checked/selected. По умолчанию
условие должно стать истинным после действия; `--allow-already` явно разрешает исходно
истинное условие. `--expect-window '<точный заголовок>'` разрешает новое окно того же процесса,
которого не было перед действием. Простые `--click`/`--expect` остаются совместимыми.

`--dry-run` не вводит ничего и возвращает `performed: false, verified: false`. В рабочем режиме
успех требует `performed: true, verified: true`. Ошибка может означать частичное выполнение:
сначала новое наблюдение, никакого слепого повтора. Проверка не исключает смену фокуса человеком
между проверкой и событием ОС; нужен свободный стол. В MCP JSON идёт в `structuredContent`,
снимок — изображением, если он запрошен.

### Человек за устройством

```sh
ferry info WIN-11-2 --json
ferry select --os windows --desktop
ferry desk WIN-11-2 take 10 --note 'гоняю e2e ~10 мин'
ferry ask WIN-11-2 'Подтвердите запрос доступа ferry, если согласны' --id access-check --timeout 600
ferry ask WIN-11-2 --poll access-check --wait 30
ferry ask WIN-11-2 --cancel access-check
```

`info`/`select` показывают возраст последнего неинжектированного ввода, замеченного ferry.
Хранятся только времена: без клавиш, координат и содержимого окон. Если наблюдатель не имеет
доступа, ещё не видел ввод или данные устарели, значение неизвестно. Это сигнал активности,
не доказательство отсутствия человека и не разрешение занять его стол.

Заметка брони отображается в подсказке трея и на рамке во время действия. `ask` показывает
человеку вопрос с источником и кнопками «Готово»/«Не могу выполнить». Закрытие окна не означает
согласие; действуют истечение срока и отмена. Повторный ID идемпотентен. Пароли и коды вводятся
человеком непосредственно в целевом приложении, ferry их не запрашивает. Ответ `done` —
сообщение человека, после которого агент отдельно проверяет результат. Окно ferry не может
оказаться поверх защищённого рабочего стола UAC; человек отвечает после выхода из него.
