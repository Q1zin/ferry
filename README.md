# ferry

Разработка на нескольких машинах локальной сети: на этом компьютере (хаб) пишешь код, а собираешь, запускаешь и смотришь на экран — на любом узле, в том числе на настоящем рабочем столе Windows. Рассчитан и на человека, и на Claude: всё — обычные команды с выводом и кодом выхода.

```sh
ferry ls                                     # узлы: на связи ли, отвечает ли рабочий стол
ferry run win-10 -- cargo test               # sync + команда в том же подкаталоге проекта на узле
ferry run win-10 --desk -- bunx playwright test --project=live --reporter=line
ferry shot win-10                            # снимок экрана → ~/.ferry/shots/win-10.png
ferry pull win-10                            # правки, сделанные на узле, — сюда
ferry stop win-10                            # снять всё, что запущено через --desk
```

`ferry` без аргументов — полный список команд.

## Как устроено

- **Узлы** — Host-блоки в `~/.ferry/ssh_config`. `ferry add` подключает его первой строкой `~/.ssh/config` (`Include`), поэтому `ssh win-10`, `scp` и `git push win-10:…` работают и напрямую. ControlMaster держит одно соединение на узел — остальные команды идут без handshake.
- **Проект** `…/<имя>` хаба живёт на узле в `~/ferry/<имя>`. `sync` (и `run` перед командой) кладёт туда снимок рабочего дерева — с незакоммиченным и новыми файлами. Снимок собирается во временном индексе и коммитится вне веток: ветка и индекс здесь не меняются, а тот же снимок даёт тот же хеш, так что повторный sync почти бесплатный. Файлы из `.gitignore` (`target/`, `node_modules/`, `.env`) не ездят — `.env` один раз положи руками: `scp .env win-10:ferry/<имя>/`.
- **Правки на узле** не теряются: если перед sync на узле есть изменения, которых нет здесь, они сохраняются патчем в `~/.ferry/saved/`. `ferry pull` применяет их к рабочему дереву здесь.
- **Рабочий стол.** По SSH команды на Windows попадают в Session 0, где нет рабочего стола: окна не видны, фокуса нет. Демон `ferry daemon` запускает планировщик при входе пользователя, то есть в его сессии; `--desk` передаёт команду ему через 127.0.0.1 и возвращает вывод и код выхода.

## Узел на Windows

Нужны Windows 10 1809+ и [Git for Windows](https://git-scm.com/download/win).

На хабе (macOS), один раз:

```sh
brew install mingw-w64
ssh-keygen -t ed25519 -f ~/.ssh/ferry -N ''
cargo install --path .                                    # ferry на хабе
cargo build --release --target x86_64-pc-windows-gnu      # ferry.exe для узла
mkdir -p dist && cp target/x86_64-pc-windows-gnu/release/ferry.exe install.ps1 ~/.ssh/ferry.pub dist/
python3 -m http.server 8000 -d dist                       # раздать установщик на время установки
```

На узле, в PowerShell от администратора, под тем пользователем, на чьём рабочем столе будут идти команды:

```powershell
iwr http://<хаб>:8000/install.ps1 -OutFile $env:TEMP\ferry.ps1 -UseBasicParsing
powershell -ExecutionPolicy Bypass -File $env:TEMP\ferry.ps1 -From http://<хаб>:8000
```

Снова на хабе:

```sh
ferry add win-10 <user>@<адрес>       # user и адреса печатает установщик в конце
```

Дальше ferry на узле обновляется с хаба: `ferry update win-10 target/x86_64-pc-windows-gnu/release/ferry.exe`.

## Обрыв соединения

Когда `ferry run` прерывают (Ctrl-C, kill, таймаут), ssh закрывает канал, клиент `ferry desk` на узле падает на первой же записи вывода, и демон убивает дерево команды — за секунды. Если умерло само соединение (хаб уснул), то же делает sshd узла по `ClientAliveInterval` (ставит установщик), примерно за 30 с.

Совсем молчаливую команду (`sleep 1000` без вывода) так не снять: Win32-OpenSSH не убивает дочерние процессы закрытой сессии, а клиент без записи обрыва не замечает. Для неё — `ferry stop <узел>`. Тесты, сборки и приложение пишут вывод, их это не касается.

## Проверка

```sh
cargo test                  # снимок, кавычки, ssh_config; демон и клиент на этой машине (unix)
ferry run <узел> --desk -- notepad   # Блокнот появляется на экране узла
```
