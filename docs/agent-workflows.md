# От первого запуска к воспроизводимому результату

Возможности этой страницы появились в ferry 0.1.24. Обнови пульт и нужные узлы перед
проверкой. Наличие команды в сборке не заменяет проверку на конкретной ОС и приложении:
доступность полей Accessibility, частота кадров и инструменты зависят от устройства.

## Подключение Claude Code и Codex

В приложении открой **Подключить агента**. Оно показывает CLI, skill и MCP каждого агента,
помогает добавить ferry в PATH и запустить первую фоновую проверку. То же из терминала:

```sh
ferry setup status
ferry setup install claude
# Либо для Codex:
ferry setup install codex
ferry setup smoke local
ferry check list
```

Поддерживаются именно Claude Code и Codex. Их CLI нужно установить заранее. Setup добавляет
MCP через официальный CLI агента с абсолютным путём к текущему ferry и устанавливает skill:
`~/.claude/skills/ferry/SKILL.md` или `~/.agents/skills/ferry/SKILL.md`. Чужую конфигурацию MCP
с именем ferry и вручную изменённый skill он не перезаписывает. Перезапусти сессию агента,
чтобы загрузить интеграцию. Настройка не меняет связи, доверие и разрешения устройств.

`setup smoke DEVICE` создаёт отдельный профиль внутри `~/.ferry/onboarding`, запускает
короткую фоновую команду и сохраняет JUnit. Она не использует ввод или экран, не изменяет
проект. Следи за полученным ID через `check status ID`; принятие задачи ещё не означает успех.

Для своего проекта:

```sh
ferry init --template smoke
ferry check smoke --devices local --id first-smoke
```

`init` создаёт `ferry.checks.json`, только если его ещё нет. Есть шаблоны `smoke`, `tauri`,
`electron`, `web`, а также `--root PATH`. Команда `test` в шаблонах — отправная точка:
настрой её под test runner проекта и добавь JUnit, когда нужен результат отдельных тестов.

## История, сравнение и переносимый отчёт

```sh
ferry check list --limit 50
ferry check list --before 'CREATED:ID'
ferry check status first-smoke
ferry check compare baseline-id candidate-id
ferry check export candidate-id --dest ./evidence/candidate
```

В приложении вкладка **Прогоны** показывает поиск по профилю/ID/устройству, фильтр состояния,
длительности, этапы с точными run ID, JUnit и артефакты. До 200 testcase на цель видны в
предпросмотре (общий объём ограничен 1 МиБ); полный сохранённый XML находится в отчёте. Гистограмма — наблюдённые
длительности прогонов, не performance benchmark. Для сравнения выбери базовый прогон.

Сравнение сопоставляет `[device, suite, class, name, file]` и требует одинаковых профилей и их имён, проекта (root/name/prefix),
упорядоченной матрицы устройств/ОС и полного однозначного индекса testcase. При неполных данных оно
возвращает `comparable: false`, а не «регрессий нет». Добавленные и исчезнувшие тесты
отмечаются отдельно; новые падающие тесты тоже дают код 1, пропуски и удаление не считаются
исправлением. Разные checkout roots несопоставимы: remote origin не сохранён как доказанная
идентичность репозитория. Индекс ограничен 20 000 testcase / 4 МиБ; исходный JUnit — 16 МиБ.

Export собирает все цели и этапы в каталог и отдельный ZIP: отчёт JSON, метаданные,
логи, тесты и доступные артефакты, включая финальный снимок, видео и video-manifest.json,
если они были. Промежуточные JPEG-кадры не дублируются: manifest содержит frames_included:false. Каталог назначения
должен быть новым. Предел собираемых доказательств — 512 МиБ; `complete: false` и `errors`
описывают недоступные файлы, устройства и незавершённые операции. Проверяй их перед
передачей пакета. Экспорт не дорисовывает отсутствующие доказательства. Из приложения
ZIP сохраняется в `~/Downloads/ferry-reports`, в браузере скачивается как файл.

## Очередь на подходящее свободное устройство

```sh
ferry queue add smoke --file ferry.checks.json --devices all --wait 600 --id smoke-queue
ferry queue status smoke-queue
ferry queue list
ferry queue cancel smoke-queue
# После обрыва пульта/связи — продолжить ту же операцию:
ferry queue resume smoke-queue
# Повторить завершённую операцию с теми же исходниками/профилем под новым ID:
ferry queue restart smoke-queue
```

`--devices` принимает `all`, `local`, `os:windows` или имена через запятую; `--os` дополнительно
ограничивает ОС. `--wait` 1–86400 секунд ограничивает ожидание назначения; `timeout` профиля
ограничивает уже выполняющуюся проверку. Профиль и снимок git фиксируются при постановке.
Назначение сохраняет стабильный ID устройства до запуска. `--home`, `--no-sync`, `--isolated`
подчиняются правилам check. Сохранённый git-снимок очередь всегда запускает в изолированной
копии, включая headless-профиль с одной командой. У --home и --no-sync снимка нет: фиксируется
только профиль, а файлы уже существующего рабочего каталога могут меняться.

Очередь допускает до двух операций одновременно и не более одной на устройство. Она
проверяет оболочку, инструменты, режим, ресурсы; desktop требует свободной брони,
незаблокированного экрана и минимум 30 секунд без физического ввода. Неизвестное присутствие
откладывает GUI. Это консервативный фильтр, а не разрешение нарушить указания пользователя.
Headless может идти в режиме «не трогать рабочий стол».

При неизвестном исходе запуска слот остаётся занятым: автоматического повтора или переноса
на другую машину нет. Сначала смотри status, затем resume; новый ID вслепую может дублировать
полезную работу. Без работающего пульта очередь не делает назначения; watchdog нет.

Для разовой команды на матрице с раздельным выводом:

```sh
ferry run all --grouped --device WIN-11-2 -- 'cargo test'
```

`--device` пересекается с выбранной матрицей. Результат и раздельные stdout/stderr сохраняются
в `~/.ferry/outputs/run-.../report.json`; предел — 64 устройства, 8 параллельных команд,
64 МиБ вывода на устройство. Это обычные команды, а не очередь check.

## Декларативные шаги по собственному окну

Готовый JSON: [examples/save.workflow.json](examples/save.workflow.json). В примере
Accessibility ID `editor`, кнопка `Save` и индикатор `Saved` — контракт тестового приложения;
замени их реальными точными локаторами из `observe --structured`. Поле уже должно иметь
фокус и ожидаемое исходное значение; ввод дописывает текст, не очищает поле автоматически.

```sh
ferry workflow validate docs/examples/save.workflow.json --param text=Hello
ferry workflow run docs/examples/save.workflow.json --device WIN-11-2 \
  --job app --run RUN_ID --window 'My App exact title' --param text=Hello --dry-run
```

После просмотра плана убери `--dry-run` для реального ввода **только в своём доступном окне**.
Задачу приложения предварительно запусти через ferry; передай её точный живой run ID.
Workflow не запускает приложения, не переводит фокус и не выбирает другое окно сам.
Каждый шаг повторно проверяет владельца окна, локаторы, предусловия и результат.

JSON содержит `schema_version: 1`, `name`, до 32 параметров, общие `preconditions` и
1–100 `steps`. Параметры `${text}` подставляются как строки, без исполнения кода.
У шага есть уникальный `id`, необязательные `preconditions`, `action`, `target`, обязательный
`expect`, `timeout` 0–30 секунд и `allow_already` (по умолчанию false). Действия:
`{"click":{"name":"Save"}}`, `{"key":"ctrl+s"}`, `{"type":"Hello"}`.
Без action шаг только проверяет условие. Assertions используют locator и property
exists/absent/value/enabled/focused/checked/selected. `new_window` допускает только новое
окно того же процесса с точным заголовком.

Неизвестное свойство, неоднозначный локатор или неполное дерево не подтверждают успех.
Проверяемое изменение должно быть false→true, если явно не задано `allow_already`.
Автоматических retry/resume нет: после ошибки сначала новое observe. Dry-run возвращает
план, а не успешный тест; зависимые будущие предусловия могут не выполниться, поскольку
реального ввода не было. Сохрани JSON результата и пути evidence.

## Запись собственного окна и просмотр

Вкладка устройства **Экран** даёт живой просмотр основного дисплея с запросом до 10 кадров/с.
Реальная частота зависит от сети, кодирования и декодирования. Ввод по умолчанию выключен;
кнопка **Управлять** явно включает управление с бронью, отключение освобождает свою бронь.
Движение курсора включается отдельно. Режим узла и существующая бронь по-прежнему действуют.

Для записи нужен `ffmpeg` **на пульте**: в PATH, `~/.local/bin`, `/opt/homebrew/bin` или
`/usr/local/bin`; автоматически он не устанавливается. Записывается точное окно процессов конкретного запуска, а не чужой экран:

```sh
ferry capture start WIN-11-2 --job app --run RUN_ID \
  --window 'My App exact title' --id recording-one --fps 10 --max-seconds 300
ferry capture status recording-one
ferry capture stop recording-one
```

`stop` завершает MP4 и manifest с исходными временными метками. Потеря окна/задачи/связи,
20 секунд без кадров и ограничения размера дают частичный результат с явной ошибкой.
Предел — 128 МиБ кадров, 128 МиБ видео и 18 000 кадров. Запись не продлевает разрешение
на стол; следи за собственной сессией/бронью. Незавершённая запись не считается доказанным
успешным видео.

В check добавь `record: {"window":"My App {run}","fps":10,"max_seconds":300}` к профилю с
`headless: false` и `launch`. Полный [пример профиля](examples/record.checks.json) нужно
адаптировать: заменить команды сборки/запуска/тестов и обеспечить указанный заголовок окна.
Check стартует запись после готовности приложения, завершает её и включает evidence в export:

```sh
ferry check desktop-recorded --file docs/examples/record.checks.json --devices WIN-11-2 --id video-check --detach
ferry check status video-check
ferry check export video-check --dest ./evidence/video-check
```

## Локальная веб-панель

```sh
ferry server --port 8080
```

Открой URL с токеном, напечатанный в JSON. Сервер слушает только `127.0.0.1`, проверяет Host,
Origin и Bearer-токен; интерфейс убирает токен из адресной строки и хранит его в sessionStorage
этой вкладки. Перезапуск сервера создаёт новый токен. Остановка — Ctrl+C в его терминале.
Публикация в LAN и изменение доверия не входят в эту команду.

По умолчанию доступны устройства, история, детали, сравнение и скачивание отчётов.
`--allow-actions` дополнительно разрешает продолжение и отмену существующего check.
Веб-панель не устанавливает агенты, не меняет устройства и не принимает произвольные shell
команды. Вопросы человеку и коды связывания в неё не передаются. Export ограничен 512 МиБ
на скачиваемый архив; более крупный пакет забирай через CLI. История и экспорты автоматически
не удаляются.

Release включает собранный Vue-интерфейс в CLI. Для разработки сначала `bun run build` в
`apps/ferry`, затем `cargo build -p ferry`; либо укажи `--assets apps/ferry/dist` существующей
сборке CLI. Сервер не обслуживает симлинки и пути за пределами каталога assets.
